# Friction log

Everything confusing or broken we hit with Amazon tools (Fire TV sample app, Android TV emulator, AWS docs and services), with the date and what we did about it. Newest first.

Add an entry the moment something slows you down: what you expected, what happened, how long it cost, the workaround.

| Date | Tool | What happened | Impact | What we did |
|---|---|---|---|---|
| 2026-10-23 | Fire TV (no Fire OS emulator) | We have no Fire TV device, and there is no emulator for Fire OS apps (the Vega Virtual Device is for Vega OS apps only). The rules ask for the demo on a device or simulator. | Severity: High. Nearly missed the demo-video requirement | Used the Android TV emulator with the Android 11 (API 30) TV image, the base of Fire OS 8, and recorded the app there. Suggestion: publish a Fire OS emulator image or an official "Fire TV" Android TV emulator profile. |
| 2026-10-23 | Android SDK / Gradle downloads | On an unstable connection, `sdkmanager --install` stopped with "An established connection was aborted by the software in your host machine" after 3 hours and left the NDK folder empty. The Gradle wrapper failed with `java.net.SocketException: Connection reset` at 50% and starts over from zero each time. | Severity: High. About 3 hours lost on the deadline day | Downloaded the NDK zip (`android-ndk-r27b-windows.zip`) and Gradle with `curl.exe -C - --retry` (resumes after drops), unpacked the NDK by hand, and pointed `distributionUrl` at the local zip. Suggestion: resumable downloads in sdkmanager and the Gradle wrapper. |
| 2026-10-23 | Fire TV sample: Android release build on Windows | Building from a short `subst` drive (to avoid long paths with spaces) made Kotlin's incremental compiler fail with "Could not close incremental caches … this and base files have different roots", because node_modules resolve to the real `C:\` path. | Severity: Medium. Build errors, then slow fallback compiles | Set `kotlin.incremental=false` and `kotlin.compiler.execution.strategy=in-process` in `android/gradle.properties`. Suggestion: document Windows path limits and a supported short-path setup in the sample README. |
| 2026-10-23 | Fire TV sample: Metro in `createBundleReleaseJsAndAssets` | The release JS bundle failed: `Unable to resolve module ./node_modules/expo/AppEntry.js from P:\/.` Expo used the monorepo root as Metro's server root, but `expo` is installed only in `apps/tv/node_modules` (Yarn `nmHoistingLimits: workspaces`). | Severity: High. No APK | Built with `EXPO_NO_METRO_WORKSPACE_ROOT=1`, so the 1,244-module bundle builds from the app folder. Suggestion: set this (or a `index.js` entry) in the sample, since its own Yarn setup triggers the problem. |
| 2026-10-23 | Fire TV sample: react-native-video | Dex merge failed: `Type androidx.media3.exoplayer.dash.DashMediaSource$Factory is defined multiple times`, then the same for `HlsMediaSource$Factory`. With DASH/HLS turned off in the sample's `app.json`, react-native-video compiles its own stub classes, while another dependency brings in the real media3 modules. | Severity: High. No APK | Set `RNVideo_useExoplayerDash=true`, `RNVideo_useExoplayerHls=true` and `RNVideo_useExoplayerRtsp=true` in `android/gradle.properties`; the release APK then built in 2.5 min. Suggestion: ship the sample with these on, or note the conflict in its README. |
| 2026-10-21 | AWS CLI (`aws login`) | The browser sign-in session expired during the build. `aws login` waits for a callback on 127.0.0.1; when the browser that opened wasn't the one we were signed in to, it waited forever. `aws login --remote` asks to paste a code back, which failed from an embedded terminal. Errors only say "session has expired". | Deploys blocked ~40 min | Ran `aws login` in the background, copied the printed URL into the browser we were signed in to, and let the localhost callback finish. Deploy scripts now check `aws sts get-caller-identity` first (documented in DEMO_SCRIPT.md). |
| 2026-10-21 | Amazon Polly (generative engine) | A first-time generative sentence took a few seconds; our 4 s Polly timeout aborted it, so Spanish and other new lines came back silent while cached English lines worked, which looked like "Spanish has no voice". | Silent coach in new languages | Raised the Polly deadline to 9 s (HTTP API cap is 30 s) and pre-synthesise the in-game cue pack per language. |
| 2026-10-20 | Amazon Polly (generative engine) | Generative voices reject every SSML `<prosody>` tag (`InvalidSsmlException`, even `rate="fast"` or `volume`), and the docs table is easy to misread. | Couldn't slow the calm voice on generative | Coach and kids use generative voices; the calm voice stays on the neural engine with `<prosody rate="90%">`; a generative failure retries on neural. |
| 2026-10-20 | AWS SAM CLI on Windows | SAM prints progress to stderr; with `$ErrorActionPreference = 'Stop'`, Windows PowerShell turns that into a terminating error whenever output is captured (`2>&1`, `*>`), so `sam build` "fails" after its first line. | Deploy looked broken twice | Deploy scripts set `ErrorActionPreference = 'Continue'` around native tools and check `$LASTEXITCODE` instead. |
| 2026-10-19 | AWS Lambda (cold start) + Amazon Polly | The first `POST /story` of a session (Lambda cold start, then Polly synthesis and an S3 upload) took long enough that the chapter-1 narration missed its 10-second intro window on the TV. | First chapter showed a placeholder | The TV now fetches all five chapters in parallel when the session starts; Polly audio is cached in S3 by text, so repeat plays are instant. |
| 2026-10-19 | Amazon Bedrock (new account) | First real Converse test calls from `check-bedrock.ps1`: **Claude Haiku 5.5** (`us.anthropic.claude-haiku-5-5`) is listed as an inference profile but fails with an error ending "For additional access options, contact AWS Sales"; **Claude Haiku 4.5** fails until the Anthropic use-case form is filled ("If you have already filled out the form, try again in 15 minutes"); **Nova Lite** fails with "Too many tokens per day" before a single successful call. Three different blockers on a brand-new account, none mentioned on the model cards. | AI features blocked on day 1 | Deploying anyway: every Bedrock call falls back to templates. Next: submit the Anthropic use-case form and ask for a Nova daily-token quota increase in Service Quotas (update this row with the outcome). Made the script print the full error text. |
| 2026-10-19 | Fire TV sample | After a clean `yarn install`, the app's `typecheck` script fails: TypeScript can't resolve `react-native` etc. from `packages/shared-ui` (Yarn's `nmHoistingLimits: workspaces` keeps them in the app's node_modules; only Metro is told where to look). With resolution fixed, 11 type errors remain in the sample's own code (remote-control key map, video player, Home/Settings screens). | Can't use `tsc` as a safety net out of the box | Type-checked our code with a temporary `paths` mapping: 0 errors in PlayMotion code. The sample errors don't affect the Babel/Metro build. |
| 2026-10-19 | Windows setup | After installing Node with winget, an already-running Windows Terminal kept the old PATH, so `corepack`/`yarn` were "not recognized" even in new tabs; `corepack enable --install-directory "%APPDATA%\npm"` also crashed with ENOENT because that folder didn't exist yet; and PowerShell's default execution policy blocks `npm.ps1`. | ~30 min | Created the folder, used `npm.cmd` / full path to `yarn.cmd`, documented quitting Terminal fully. |
| 2026-10-18 | Fire TV sample (react-native-multi-tv-app-sample) | The Expo app is on `expo ~54.0.0` but pins `expo-font ~13.0.0`, `expo-constants ~17.0.0` and `expo-splash-screen ~0.29.0` (Expo SDK 52 versions). The lockfile resolves both 13.x and 14.x of expo-font. | Possible version warnings / native mismatches; unclear which is intended | Kept the sample's versions for now so the fork matches upstream; will run `npx expo install --check` after the first emulator build and log the result. |
| 2026-10-18 | Fire TV sample | The app's UI is not in the app folder: navigation, screens and remote-control handling live in the `@multi-tv/shared-ui` workspace package, so "fork `apps/expo-multi-tv`" really means forking two folders plus the Yarn 4 workspace setup. `apps/expo-multi-tv/app/configureRemoteControl.ts` also imports a path (`../shared-ui/...`) that doesn't exist (the file is unused). | ~30 min reading the repo | Copied `apps/expo-multi-tv` → `apps/tv` and `packages/shared-ui` as-is, kept Yarn 4 workspaces, put PlayMotion code in `packages/shared-ui/src/movewell`. |
| 2026-10-18 | Fire TV sample on Windows | Scripts use POSIX `EXPO_TV=1 expo start` syntax and the README assumes macOS/Linux; Yarn 4's built-in shell handles it, but running the same scripts with npm on Windows fails. | Confusing on Windows | Switched the scripts to `cross-env`; documented Corepack setup without admin rights and the short-path tip for Android builds. |
| 2026-10-18 | Amazon Bedrock | The model ID for the newest Claude Haiku isn't something you can guess. On-demand Converse calls need a cross-region **inference profile** ID (`us.anthropic...`), not the base model ID, and the console model catalog doesn't show the ID next to a "copy for Converse" button. | ~20 min of reading docs | Wrote `scripts/check-bedrock.ps1`: lists inference profiles, test-calls each with the exact request the Lambda sends, prints the deploy command. Model IDs are a SAM parameter, not hard-coded. |
| 2026-10-18 | Amazon Bedrock | Anthropic models need a one-time use-case form per account before the first call; until then, calls fail with an access error that doesn't say "fill in the form". | Blocks AI features on a fresh account | `check-bedrock.ps1` prints this hint on failure. The app falls back to Nova Lite, then to templates, so the demo never breaks. |
| 2026-10-18 | API Gateway WebSocket | You can't send a message to a client inside the `$connect` handler (the connection isn't open yet), so the TV can't receive its pairing code on connect. | Design change | TV sends `{"action":"host"}` right after the socket opens and gets the code back as a normal message. |
| 2026-10-18 | API Gateway HTTP API | Integration timeout is capped at 30 s, which is tight for LLM + TTS chains. | Design constraint | Every Bedrock call has its own deadline (3.5–12 s) and a model fallback chain; Polly runs with a deadline (4 s at first, 9 s since the generative voices, see 2026-10-21); templates fill in. |
| 2026-10-18 | CloudFront + S3 (OAC) | The standard SPA trick (403/404 → `/index.html`) also hides real missing files, e.g. a Polly audio file that failed to upload. | Debugging trap | The API only returns an audio URL after the S3 upload succeeds; otherwise it returns `url: null` and the TV uses on-device TTS. |
